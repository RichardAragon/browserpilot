The original task opened one form and submitted Create once. Development retries retained that form, completed the approved fields and verified them in an independent browser view. All platform changes used browser controls with platform-specific adapters disabled.

Changes

  • Recognize filter removal from rendered search-region context
  • Recheck search context before acting; return rejected navigation to the planner
  • Discover options in explicitly linked or unique adjacent accessible menus
  • Preserve expanded dropdowns instead of toggling them closed
  • Resolve submission by reviewed button text and attributes
  • Resume unfinished input only in the original live approved form, with before/after drift checks and no prior final submission
  • Journal final submission intent separately; lost forms and uncertain submissions remain inspection-only
  • Batch visible control observation while retaining node handles; reuse the observed object workspace

Validation

158 automated tests passed, plus real-browser filter, dropdown and stale-context checks. The final successful attempt took 57.656 seconds. This excludes earlier development iterations and is not a performance benchmark.

The installed Windows package also verified the same Opportunity after restart in 37.485 seconds. The journal still records exactly one final creation.

Scope

  • Browser-only creation and update remain a preview, not universal compatibility.
  • This does not add deletion, bulk operations, permission changes or arbitrary workflow execution.
  • Approval scopes the requested record and fields; it does not authorize unrelated actions.
  • Browser checks cannot provide server-side uniqueness or atomic isolation.
