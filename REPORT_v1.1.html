BROWSERPILOT · 1.1 PREVIEW

Generic creation, with a memory for each connection.

The same browser controller and real LLM planner created and verified synthetic records in Dolibarr and Odoo, with platform-specific adapters disabled. Each connection now keeps its own evidence-backed notes, user corrections and revision history.

103 automated tests passed. Live checks covered setup, generic creation, duplicate prevention, restart recovery and LLM note generation. API-level parity remains unproven.

What changed

  • AI setup discovers the broad record workspace and visible controls, with optional encrypted sign-in credentials kept out of model prompts.
  • Generic creation searches for duplicates, discovers a blank form, requests field review, records intent before edits, and independently searches and reopens the result.
  • Connection notes learn navigation, search, field and recovery lessons from local history. The model updates them after completed attempts; future planning receives them as advisory context.
  • Users can add corrections and restore revisions. Concurrent edits use revision checks so an AI update cannot silently overwrite a user's changes.

Reliability findings

Odoo's name input was an autocomplete control with an example company placeholder inside its main heading. Generic semantic grounding was expanded to handle this, without adding an Odoo selector. Dolibarr exposed a search-click timeout and inconsistent model field keys; the controller now handles navigation readiness explicitly and lets the planner correct rejected mappings before editing.

Each successful creation has exactly one recorded Create click. Both deliberate duplicate tasks stopped before opening a creation form. Odoo's completed operation was verified after restart without replaying creation. The abandoned VEGA operation remained uncertain: its retry searched for the outcome and did not reopen New. Its conservative fence remains intact.

Notes in practice

Odoo learned its Name filter and placeholder-based field conventions; Dolibarr learned its Third-party name mapping and unrestricted-list search scope. Failure hypotheses are distinguished from observed lessons. Saved Odoo user guidance survived automatic consolidation, and both note sets persisted into the packaged executable.

Timing and scope

The successful Odoo creation took 29.453 seconds to prepare for review and 44.578 seconds after approval (7 execution decisions). Its subsequent restart readback took 37.140 seconds. The packaged Dolibarr duplicate check took 16.969 seconds and one planner decision. These are single local samples; they exclude human review time and do not establish that memory improved speed. Learning runs separately in the background.

Two earlier Odoo attempts remain uncertain. Salesforce and HubSpot were not live tested. Browser checks cannot enforce atomic server locks or uniqueness against a simultaneous external writer. Notes can be mistaken and are never permission to skip current-page checks.

Open the app

Unzip the Windows package and open BrowserPilot.exe alongside its _internal folder. Choose a model in Settings, then add a website. Find memory under Connections → Platform notes.
